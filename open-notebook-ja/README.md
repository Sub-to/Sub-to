# Open Notebook を日本語で使う

[Open Notebook](https://www.open-notebook.ai/) は Google NotebookLM のオープンソース代替で、
Docker で自分のマシンに立てて使えます。PDF・Web ページ・YouTube・音声・動画を放り込んで、
AI と対話し、ノートを取り、ポッドキャストを生成できます。

このディレクトリは、**Open Notebook を日本語で快適に使うための設定一式と手順書**です。
上流 v1.14.0 (commit `2d2df8a`, 2026-09-05 時点) を実機で調べた結果に基づいています。

---

## 結論: 日本語でどこまで使えるか

| 機能 | 日本語対応 | 備考 |
|---|---|---|
| **画面 UI** | ◎ そのまま日本語 | `ja-JP` を公式サポート。v1.14.0 で訳文が全面的に見直し済み |
| **日本語入力** | ◎ | IME 変換中に入力が重くなる問題は v1.14.0 で修正済み |
| **AI との対話・要約** | ◎ | ただし**日本語で答えさせる指示は自分で入れる**（本手順に同梱） |
| **ベクトル検索** | ◎ | 埋め込みモデルの設定が必要 |
| **テキスト検索（全文検索）** | ✕ **使えない** | 日本語を単語に分割できない。[詳細](docs/japanese-search.md) |
| **日本語 PDF の読み込み** | ○ | Docling を有効にすると精度が上がる |
| **ポッドキャスト生成** | ○ | エピソードプロファイルで言語に `ja-JP` を指定 |
| **Ask（横断質問）** | △ | v1.14.0 に**日本語の回答が途中で切れる不具合**あり（後述） |

---

## 必要なもの

- Docker Desktop（または Docker Engine + Compose v2）
- AI プロバイダの API キー 1 つ以上（OpenAI, Anthropic, Google など）
  - ローカルで完結させたい場合は Ollama や LM Studio でも動きます
- ディスク 5GB 程度（Docling を有効にする場合はさらに数 GB）

## 1. 導入（5〜10分）

このディレクトリの中身をそのまま使います。

```bash
# 設定ファイルを用意
cp .env.example .env

# 暗号化キーを生成して .env に書き込む（必須）
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
# → 出力された文字列を .env の OPEN_NOTEBOOK_ENCRYPTION_KEY= に貼る

# 起動
docker compose up -d

# ログを確認（初回は Docling のインストールで数分〜十数分かかります）
docker compose logs -f open_notebook
```

起動したら http://localhost:8502 を開きます。REST API は http://localhost:5055 です。

> **暗号化キーについて**: この鍵で API キーを暗号化して保存します。
> あとから変更すると保存済みの API キーが復号できなくなるので、最初に決めて変えないでください。

同梱の `docker-compose.yml` は上流版に以下を足しています。

- `PROMPTS_PATH=/app/ja-prompts` … 日本語で回答させるプロンプト上書き（下記 3.）
- `OPEN_NOTEBOOK_ENABLE_DOCLING=true` … 日本語 PDF の抽出精度向上
- 暗号化キーが未設定なら起動時に明示エラーで止まるガード

---

## 2. 画面を日本語にする

ブラウザの言語が日本語なら**自動で日本語表示**になります
（i18next がブラウザ設定を見て `ja-JP` を選びます）。

手動で切り替えるときは、**左サイドバーの言語切り替え**から「日本語」を選びます。
選択内容はブラウザの localStorage に保存されるので、次回以降も日本語のままです。

対応言語は 14 種類（日本語・英語・中国語簡体/繁体・ポルトガル語・スペイン語・
フランス語・ドイツ語・イタリア語・ロシア語・ベンガル語・カタルーニャ語・ポーランド語・トルコ語）。

---

## 3. AI に日本語で答えさせる

**ここが一番大事です。** Open Notebook の内蔵プロンプトには出力言語の指示が一切ありません。
そのため英語のソースを読み込むと、日本語で質問しても英語で返ってくることがあります。

同梱の `ja-prompts/` がこれを解決します。`docker-compose.yml` で
`PROMPTS_PATH=/app/ja-prompts` を設定済みなので、**追加の作業は不要**です。

仕組み: Open Notebook が使うテンプレートエンジン (ai-prompter 0.4.0) は
`PROMPTS_PATH` → `/app/prompts` の順にテンプレートを探し、最初に見つかったものを使います。
`ja-prompts/` に置いた 3 つだけが差し替わり、残りは上流のまま使われます。

| 上書きするファイル | 効果 |
|---|---|
| `ja-prompts/chat/system.jinja` | ノートブックでのチャットが日本語になる |
| `ja-prompts/source_chat/system.jinja` | 個別ソースとの対話が日本語になる |
| `ja-prompts/ask/final_answer.jinja` | Ask の最終回答が日本語になる |

中身は上流の原文をそのまま残し、先頭と末尾に日本語で出力するルールを足しただけです。
上流を更新したときの差分確認が楽になるようにしています。

**変換（Transformations）** は上流プロンプトを経由せず、書いた指示がそのまま使われます。
日本語の変換プロンプト集を [`transformations/README.md`](transformations/README.md) に用意しました
（要約・重要ポイント・用語集・批判的レビュー・想定問答）。UI からコピペで登録してください。

## 4. モデルの設定

**モデル** ページで、使うプロバイダの API キーを登録し、用途ごとに既定モデル（⭐）を割り当てます。
環境変数でも API キーを渡せますが上流で非推奨扱いなので、**UI から登録**してください。

### 言語モデル（チャット・要約用）

日本語の読み書きが得意なモデルを選びます。Claude、GPT、Gemini の現行世代はいずれも十分です。
ローカルで動かすなら Ollama 経由で日本語対応モデルを使えますが、
要約品質はクラウド API と差が出ます。

### 埋め込みモデル（**必須**）

**日本語では検索がベクトル検索頼みになるため、埋め込みモデルの設定は必須です。**
多言語対応のモデルを選んでください（OpenAI の `text-embedding-3-small` / `-large`、
Google、Cohere、Voyage、Mistral など）。

設定後、**設定 → 「Embeddingと検索」→「デフォルトEmbeddingオプション」** を有効にします。
これをしないとソースがベクトル化されず、検索も Ask も機能しません。

> 後から埋め込みモデルを変更した場合は、**「Embeddingを再構築」** を実行してください。
> 古いモデルのベクトルと新しいクエリは比較できないため、変更しただけでは検索がおかしくなります。

### 音声モデル（ポッドキャスト・文字起こし用）

- **TTS（読み上げ）**: OpenAI、Google、ElevenLabs などが日本語音声に対応しています。
  まず 3〜5 分の短いエピソードで発音を確認してから本番に使ってください。
  固有名詞や漢字の読み間違いはプロバイダによって癖が違います。
- **STT（文字起こし）**: 日本語音声・動画を読み込む場合に必要です。

## 5. 日本語運用の勘所

### 検索は「ベクトル」を使う

日本語のテキスト検索（全文検索）は**動きません**。
アナライザが日本語を単語に分割できず、句読点で区切られた文節がまるごと 1 トークンになるためです。
「人工知能」で検索しても、その語を含む文書はヒットしません。

実測データと、N-gram による回避が効かない理由は [`docs/japanese-search.md`](docs/japanese-search.md)
にまとめました。手元で再現するスクリプトも同梱しています。

```bash
./docs/verify-japanese-search.sh
```

**対応**: 検索画面では検索方式を「ベクトル」にしてください。
型番や英語の固有名詞（`GPT-4o` など）を厳密に探すときだけテキスト検索が使えます
（日本語の文中でも英数字部分は分割されるため）。

### 日本語 PDF は Docling で読む

`docker-compose.yml` で `OPEN_NOTEBOOK_ENABLE_DOCLING=true` を有効にしてあります。
Docling はレイアウト解析と OCR に対応しており、日本語の表組みやスキャン PDF で
標準の抽出より明確に精度が上がります。**設定 → コンテンツ処理** でドキュメント処理エンジンを
「自動（推奨）」または「Docling」にし、スキャン PDF を扱うなら「OCRを有効にする」も入れます。

初回起動時に数 GB をダウンロードするため、最初の `docker compose up` だけ時間がかかります
（ダウンロードは `notebook_data` ボリュームにキャッシュされ、2 回目以降は速いです）。
不要なら compose のこの行をコメントアウトしてください。

### YouTube の日本語字幕を優先させる

字幕言語の優先順位の既定値は `["en", "pt", "es", "de", "nl", "en-GB", "fr", "hi", "ja", ...]` で、
**英語が最優先・日本語は 9 番目**です。日本語動画に英語の自動翻訳字幕が付いていると、
そちらが取り込まれることがあります。

この設定は現在 UI に項目がないため、REST API から変更します。

```bash
curl -X PUT http://localhost:5055/api/settings \
  -H "Content-Type: application/json" \
  -d '{"youtube_preferred_languages": ["ja", "en"]}'
```

`OPEN_NOTEBOOK_PASSWORD` を設定している場合は `-H "Authorization: Bearer <パスワード>"` を足してください。

### ポッドキャストを日本語で作る

**ポッドキャスト → エピソードプロファイル** で、**「ポッドキャストの言語」に日本語 (`ja-JP`) を指定**します
（プロファイルに BCP 47 の言語コードを保持するフィールドがあります）。
あわせて、

- スピーカープロファイルの音声モデルに、日本語に対応した TTS を割り当てる
- デフォルトの台本指示（briefing）を日本語で書き直す

の 2 つをやっておくと、安定して日本語の台本と音声になります。
1〜2 分の短い設定で一度試し、読み上げの自然さを確認してから長いエピソードを作ってください。

### 長い日本語文書を扱うとき

日本語は同じ内容でも英語よりトークンを多く消費します。
長文で応答が途中で切れる、あるいはコンテキスト超過エラーが出る場合は、
より大きなコンテキスト長のモデルに切り替えてください。

## 6. 既知の問題（v1.14.0 時点）

### Ask の日本語回答が途中で切れる

**Ask（質問と検索）の 3 段階の処理が出力 2000 トークンで打ち切られる不具合**が v1.14.0 にあります。
日本語のようにトークン消費の多い言語では文の途中で切れ、
さらに検索語の生成が空になって「該当する文書がありません」と返ることがあります。

上流では修正済みですが、**2026-09-09 時点で未リリース**です（次のリリースに入る見込み）。
それまでの回避策:

- Ask ではなく、ノートブック内のチャットを使う（チャットは 8192 トークンで影響を受けません）
- 質問を小さく分割する

`docker compose pull && docker compose up -d` で新しいリリースが出ていれば取り込まれます。

### 日本語のテキスト検索

上記のとおり構造的な制約です。修正の見込みは現時点ではありません。ベクトル検索を使ってください。

## 8. 更新のしかた

```bash
docker compose pull
docker compose up -d
```

`ja-prompts/` の 3 ファイルは上流 v1.14.0 の原文をコピーして日本語指示を足したものです。
上流がこれらのプロンプトを更新した場合、上書き版は古いままになります。
メジャー更新のあとは差分を確認して取り込んでください。

上書き版には `{# UPSTREAM-BEGIN #}` / `{# UPSTREAM-END #}` というマーカー（Jinja コメントなので
プロンプト出力には現れません）が入っています。この間が上流の原文そのままです。

```bash
# 3ファイルすべてを上流の最新版と比較する
for f in chat/system source_chat/system ask/final_answer; do
  echo "--- $f ---"
  diff <(curl -s "https://raw.githubusercontent.com/lfnovo/open-notebook/main/prompts/$f.jinja") \
       <(awk '/UPSTREAM-BEGIN/{n=1;next} /UPSTREAM-END/{n=0} n' "ja-prompts/$f.jinja")
done
```

差分が出たら、`ja-prompts/<file>` のマーカー間を上流の新しい内容に置き換えれば、
日本語の指示（マーカーの外側）はそのまま残ります。

上書きをやめたいときは、`docker-compose.yml` から `PROMPTS_PATH` の行と
`./ja-prompts` のマウント行を消せば上流のプロンプトに戻ります。

### この手順書の検証状況

正直に区別しておきます。

**実際に動かして確認したもの**

- 日本語の全文検索が機能しないこと、および N-gram での回避が効かないこと
  （SurrealDB 2.3.10 に上流と同じアナライザ定義を投入して実測）
- `PROMPTS_PATH` によるプロンプト上書きが、置いたファイルだけを差し替えて
  残りは上流にフォールバックすること（ai-prompter 0.4.0 で実行）
- 同梱の `docker-compose.yml` が `docker compose config` を通ること、
  暗号化キー未設定時に明示エラーで止まること
- `ja-prompts/` の 3 ファイルが Jinja として正しくレンダリングされ、
  マーカーが出力に漏れないこと

**上流のソースコード・CHANGELOG を読んで確認したもの（実機未確認）**

- UI の日本語対応と言語切り替えの挙動（`ja-JP` ロケールと i18next の設定を確認）
- エピソードプロファイルの言語フィールド（BCP 47 コードを保持）
- YouTube 字幕言語の既定値と、それを変更する REST API
- Ask のトークン上限の不具合と、その修正が未リリースであること

**未検証（一般的な知識に基づく記述）**

- 各 TTS プロバイダの日本語音声の品質・発音の正確さ
- Docling が日本語 PDF で実際にどれだけ精度が上がるか

Open Notebook 本体を起動しての通し確認は行っていません
（この作業環境から Docker イメージを取得できなかったため）。
導入後に実際の挙動が違っていた場合は、上の区分を手がかりに切り分けてください。
