# 日本語での検索挙動 — 検証レポート

Open Notebook には「テキスト検索」と「ベクトル検索」の 2 種類があります。
**日本語では、テキスト検索はほぼ機能しません。** 実機で検証した結果と理由をまとめます。

検証対象: lfnovo/open-notebook v1.14.0 (commit `2d2df8a`) / SurrealDB 2.3.10

---

## 結論（先に）

| 検索方式 | 日本語での実用性 | 対応 |
|---|---|---|
| テキスト検索（全文検索・BM25） | ほぼ使えない | 使わない |
| ベクトル検索（埋め込み） | 問題なく使える | **こちらを使う。埋め込みモデルの設定は必須** |

Ask（質問して回答を生成する機能）も内部で検索を使うため、
**埋め込みモデルを設定していないと日本語ノートブックでは「該当なし」になりがち**です。

---

## 原因

`open_notebook/database/migrations/1.surrealql` が定義しているアナライザがこれです。

```sql
DEFINE ANALYZER my_analyzer
  TOKENIZERS blank,class,camel,punct
  FILTERS snowball(english), lowercase;
```

トークナイザは 4 つとも、英語のように**単語が区切られている前提**です。

- `blank` — 空白で分割
- `class` — 文字種（英字／数字／記号など）が変わったところで分割
- `camel` — camelCase で分割
- `punct` — 句読点・記号で分割

日本語は漢字・ひらがな・カタカナがすべて同じ「文字種（alphabetic）」として扱われるため、
`class` では分割されません。結果として、**句読点で切られた文節がまるごと 1 トークン**になります。

## 実測結果

```
入力: 機械学習は人工知能の一分野です。ディープラーニングも含まれます。

トークン: ['機械学習は人工知能の一分野です', 'ディープラーニングも含まれます']
```

この状態で検索すると、こうなります。

| クエリ | 結果 |
|---|---|
| `人工知能` | **ヒットしない** |
| `機械学習` | **ヒットしない** |
| `機械学習は人工知能の一分野です`（文節と完全一致） | ヒットする |
| `artificial`（英語・対照） | ヒットする |

短い語が偶然ヒットすることはあります。「保険、年金、税金。」のように読点で区切られていれば
`保険` は 1 トークンなのでヒットしますが、これは分かち書きができているわけではありません。
同じ文書でも `重要`（文中の部分語）はヒットしません。

なお、日本語の文中にある英数字は `class` トークナイザが拾えます。
「当社のGPT-4o活用事例について。」は `['当社の', 'gpt', '-', '4', 'o活用事例について']` となり、
`gpt` での検索はヒットします。**型番や英語の固有名詞だけはテキスト検索でも探せます。**

再現するには [`verify-japanese-search.sh`](./verify-japanese-search.sh) を実行してください。

## 試したが効かなかった回避策

SurrealDB の `ngram` フィルタで N-gram 化すれば CJK に対応できそうに見えますが、**効きません**。

```sql
-- これは期待どおりに動かない
DEFINE ANALYZER ja TOKENIZERS blank,class,camel,punct FILTERS lowercase, ngram(2,3);
```

インデックス側・クエリ側とも N-gram には正しく分割されます
（`人工知能` → `['人工','人工知','工知','工知能','知能']`）。
しかし SurrealDB の全文一致は複数トークンを**連続した並び**として照合するため、
N-gram で崩れた位置情報では一致しません。実測では以下のようになりました。

| クエリ | `ngram(2,3)` | `ngram(2,2)` |
|---|---|---|
| `保険`（2文字＝1トークン） | ヒット | ヒット |
| `人工知能` | ヒットしない | ヒットしない |
| `ディープラーニング` | ヒットしない | ヒットしない |
| `artificial`（英語） | **ヒットしなくなる** | **ヒットしなくなる** |

2 文字語しか拾えないうえ、英語検索まで壊れます。採用しないでください。

SurrealDB v2 には日本語向けのトークナイザ（kuromoji 相当）がありません。
アナライザ定義を書き換えて日本語テキスト検索を成立させる方法は、現時点では見つかっていません。

## 運用上の対応

1. **埋め込みモデルを必ず設定する。** 「モデル」ページで Embedding モデルを登録し、
   デフォルト（⭐）に指定します。日本語を含む多言語対応のモデルを選んでください
   （OpenAI `text-embedding-3-small` / `-large`、Google, Cohere, Voyage, Mistral など）。
2. **設定 → Embedding で自動埋め込みを有効にする。** これがないとソースがベクトル化されません。
3. **検索画面では検索方式を「ベクトル」にする。** 日本語で意味的に近い文書が返ります。
4. **型番・英語の固有名詞を厳密に探したいときだけテキスト検索を使う。**
